# Horizon 项目目标

## 产品定位
每天自动发现、筛选科研相关信息，帮助用户建立科研工具箱、查漏补缺，并跟进值得关注的研究方法和工具。推荐不限发布时间；成熟实用的旧工具与重要更新都可入选，质量优先于数量与热度。

## 用户期望（目标，尚非本次交付）
- 中文日报，每天最多 3–5 项，缺少高质量候选时不凑数。
- 伦敦当地时间 11:30 左右投递到 Outlook，正确处理夏令时并说明调度延迟。
- 每项说明具体科研用途、操作示例、增益与重复能力、成本、依赖、权限、局限、原始来源及核验时间。
- 同时覆盖近期发现/更新与成熟工具补缺；跟踪历史推荐和用户“已有、已用、不适合”等反馈。
- 保存可复查的日报与证据，让模型辅助判断，而不是用模型之间的共识代替验证。

## 现有项目基础
仓库已有多源采集、Profile 路由与评分、URL/主题去重、内容补充、历史搜索、Markdown 日报、邮件/Webhook 等投递和 MCP 入口，并包含 pytest 测试。已有能力不代表当前 Fork 已完成私人科研配置或部署。

## 当前交付范围
仅建立 Claude 规划/审核与 Codex 执行/测试的协作文件、任务记录、待办和科研范围。没有配置真实模型、API凭证、发信服务、定时运行或科研采集规则。ELM API 此前显示待审核；当前有效状态须后续核实，不假定已批准或兼容。

## 成功标准
推荐可追溯、具体、相关且能指导低成本试用；信息增益大于重复摘要。业务实现阶段还需验证去重、状态持久化、失败处理、额度与凭证保护、投递可靠性。不能用 Stars、发布新旧或营销承诺代替实际评价。

## 不做什么
不作为临床诊疗或投资建议系统，不杜撰研究结果，不自动运行推荐工具的未知代码，不将小红书抓取作为必备依赖，不默认公开私人日报。当前不新增功能、不改源代码、不启用部署。
